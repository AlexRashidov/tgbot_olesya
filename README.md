# Бот «Таблетка от прокрастинации»

Telegram-бот для воронки: тест «Где именно ты застреваешь перед задачей?» → результат →
метод → пример → продукт → оплата → выдача материалов. Есть фоновая цепочка прогрева
(через 24 ч / ещё 48 ч / ещё 48 ч) и напоминание о незавершённом тесте.

Стек: Python 3.12+, [aiogram 3](https://docs.aiogram.dev/), SQLite через `aiosqlite`.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env          # Linux/macOS: cp .env.example .env
```

Заполни `.env` (минимум `BOT_TOKEN` и `ADMIN_IDS`) и запусти:

```bash
python run.py
```

База создаётся автоматически по пути из `DATABASE_URL` (по умолчанию `data/bot.db`).

## Тексты в коде

Исходные тексты лежат в `bot/texts.py` (разметка HTML: `<b>жирный</b>`, `<i>курсив</i>`).
После правки файла бота нужно перезапустить. Автору удобнее менять тексты через бота — см. ниже.

## Тесты

```bash
pip install pytest
python -m pytest
```

## Как поменять тексты

**Через бота (для автора):** администратор (его ID в `ADMIN_IDS`) пишет боту `/texts`, выбирает раздел
и сообщение, нажимает «✏️ Изменить» и присылает новый текст. Жирный, курсив и ссылки делаются обычным
форматированием Telegram. Правка применяется сразу, без перезапуска. Кнопка «↩️ Вернуть исходный текст»
откатывает правку. Отмена ввода — `/cancel`.

Правки хранятся в базе (таблица `text_overrides`) поверх исходных текстов из `bot/texts.py`.

## Оплата

Бот поднимает веб-сервер (`WEB_PORT`, по умолчанию 8080) для уведомлений от платёжных систем
и для формы оплаты на лендинге. Снаружи он должен быть доступен по HTTPS — адрес указывается
в `PUBLIC_BASE_URL` (обычно nginx + certbot перед ботом).

| Адрес | Что делает |
|---|---|
| `POST /webhooks/tbank` | уведомления Т-Банка (проверяется подпись `Token`) |
| `POST /webhooks/prodamus` | уведомления Prodamus (проверяется подпись в заголовке `Sign`) |
| `POST /api/checkout` | форма на сайте: создаёт заказ и возвращает ссылку на оплату |
| `GET /api/orders/<id>` | статус заказа; ссылки на группы — только после оплаты |
| `GET /health` | проверка, что сервер работает |

### Где покупают: на лендинге

Если в `.env` задан `SITE_URL`, кнопка «Купить за 2 500 ₽» в боте (в описании продукта, «Посмотреть
содержание» и третьем сообщении прогрева) открывает лендинг сразу на форме оплаты:
`SITE_URL?tg=<Telegram ID>&utm_source=telegram_bot#pricing`.

Лендинг передаёт этот ID в `/api/checkout`, заказ привязывается к пользователю бота
(статус `pending`, теги `purchase_clicked` / `payment_pending`). После оплаты бот сам присылает
материалы, отмечает пользователя покупателем и останавливает прогрев — как при оплате внутри бота.

Если `SITE_URL` пустой, «Купить» работает по-старому: оплата внутри бота (описано ниже).

### Автоматическое подтверждение (рекомендуется)

Заполни в `.env` `TBANK_TERMINAL_KEY` / `TBANK_PASSWORD` и/или `PRODAMUS_FORM_URL` / `PRODAMUS_SECRET`
и `PUBLIC_BASE_URL`. Тогда:

1. «Купить за 2 500 ₽» → бот спрашивает почту для чека → создаёт заказ и персональную ссылку на оплату.
2. Платёжная система присылает уведомление → бот проверяет подпись и сумму → пользователь получает
   статус `customer` и ссылку `MATERIALS_URL`, прогрев останавливается, админам приходит уведомление.
3. Чек на почту отправляет сама платёжная система (у Т-Банка — при `TBANK_RECEIPT=1` и подключённой кассе).

В кабинете Prodamus в настройках уведомлений можно дополнительно указать
`<PUBLIC_BASE_URL>/webhooks/prodamus` (бот и так передаёт этот адрес в каждой ссылке).

### Покупка на сайте

Лендинг отправляет форму на `/api/checkout` и переводит покупателя на оплату. После оплаты платёжная
система возвращает его на `SITE_URL?order=<id>`, где страница ждёт подтверждения и показывает кнопки
перехода в группы из `ACCESS_TG_URL`, `ACCESS_VK_URL`, `ACCESS_MAX_URL`. Админам приходит уведомление
с ФИО, почтой и телефоном покупателя.

### Ручная проверка (запасной вариант)

Если платёжка не настроена (или не удалось создать платёж), бот показывает статичные ссылки
`PAYMENT_URL_RU` / `PAYMENT_URL_FOREIGN` и кнопку «Я оплатил(а)». Админу приходит заявка с кнопками
«Подтвердить» / «Оплата не найдена». Подтвердить можно и командой `/paid <user_id>`.

Статистика по воронке и оплатам: `/stats`.

## Фоновые задачи

`services/scheduler.py` раз в `SCHEDULER_TICK_SECONDS` проверяет базу:

- прогрев 1/2/3 — только тем, кто прошёл тест, не купил и не отписался (`/stop`);
  после третьего сообщения цепочка заканчивается;
- одно напоминание через 24 ч, если тест начат и не закончен.

Состояние хранится в SQLite, поэтому после перезапуска отправки продолжаются с того же места.
Для быстрой проверки поставь в `.env` значения `DELAY_SCALE=0.0007` и `SCHEDULER_TICK_SECONDS=10`:
интервалы сожмутся примерно до 1 / 2 / 2 минут.

## Данные пользователя

Таблица `users` содержит поля из ТЗ: `test_started`, `test_completed`, `answer_1..4`, `score_*`,
`test_result`, `product_interest`, `purchase_status`, `sales_stage`, `followup_status`.
Таблица `user_tags` хранит теги `test_started`, `result_*`, `product_viewed`, `purchase_clicked`,
`payment_pending`, `customer`, `followup_opt_out`.
Источник перехода сохраняется из ссылки вида `t.me/<бот>?start=reels`.
